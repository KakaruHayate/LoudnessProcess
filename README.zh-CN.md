# LoudnessProcess

**歌声 / 语音数据集的响度与动态规整工具。**

输入一批录制或处理条件不一致的音频片段，输出一份"响度统一、但内部仍然有动态"的数据集：

- 每条片段的**整体响度**都落在同一个按 ITU-R BS.1770 测出来的目标上；
- 每条片段**内部**的响度依然跟着音乐走（并且跟着音高走——这是音高条件化的声学模型唯一学得到的东西）。

全程不使用压缩器、不做 EQ。唯一的电平处理是：每条片段一个常数增益、一条随音高平滑变化的增益，
以及真正超限时的一个真峰值限幅器。

```
体检  →  处理  →  验收  →  听感对比
```

---

## 解决什么问题

数据集里片段之间的响度几乎从来不一致。片段来自不同的 take、不同的场次、不同的歌、
不同的人声处理链，于是"同一个元音、同一个音高"可能因为毫无音乐上的理由差上好几 dB。
对于一个预测绝对 log-mel 目标的声谱模型来说，它没有任何线索判断哪个才是本意，
于是每次推理出来的响度都在飘。

几个显而易见的做法各有短板：

| 做法 | 修好了什么 | 弄坏了什么 |
|---|---|---|
| 匹配响度（逐片段常数增益） | 整体电平 | 什么都没弄坏，但也**完全碰不到"电平随音高怎么变"这条斜率**，而不一致主要就在斜率和偏移上 |
| AGC / 响度均衡器 | 电平**和**斜率 | 斜率被一起压平，模型渲染出的动态变得呆板 |
| 人工处理 | 两者都能兼顾 | 慢，而且结果取决于谁做的 |

第二列之所以这么受限，是因为一条片段的电平并不是一个数。它可以分解成：

```
L(t) = a  +  B·p(t)  +  slow(t)  +  fast(t)
       ↑     ↑          ↑           ↑
    常数偏移  音高项    乐句级      音节级
```

- `a` —— 每条片段一个常数。**模型完全看不见它。** 这就是"合成时忽大忽小"的来源。
- `B·p(t)` —— 电平随音高变化。音高**是模型的输入**，所以这部分**可学习、可控**。
- `slow(t)`、`fast(t)` —— 真正的演唱细节，必须原样保留。

常数增益只能改变 `a`，改不了 `B`。而真实数据里 `B` 极不一致（在同一批素材里实测可以从
−3 一直差到 +17 dB/oct），模型只能在这些互相矛盾的样本之间学出一个平均值——
这就是"动态诡异"的实际含义。

本工具同时改 `a` 和 `B`，并且在数学上保证 `slow` / `fast` 分毫不动。

## 原理

### 施加到每个采样点的增益

```
gain(t) = DC + (B_tilt − B_source) · (p(t) − p̄)
```

| 符号 | 含义 |
|---|---|
| `B_tilt` | 模型**在单条片段内部**应当呈现的斜率（默认 **+6 dB/oct**） |
| `B_source` | 该来源实测的斜率，由它所有片段池化估计 |
| `p(t)`、`p̄` | 逐帧音高、该片段的能量加权平均音高 |
| `DC` | 该片段在响度轴上的位置（见下） |

`B_tilt` 的取值依据：未经处理的歌声通常实测在 **+6.8 … +8.5 dB/oct**；质量较好的商业渲染
大约在 **+6**；被重度压过的录音会掉到 **+2**。低于 +3 听感开始发平，所以 `+6` 是安全默认值。

### 片段落在哪个电平（`DC`）

```
DC = target + δ + design_offset(p̄ − p̄_ref)
```

`design_offset` 是一条线性曲线（每个半音 `+B_seg` dB）；给定容差窗 `tol` 时会在 `±tol` 处
**软饱和**：

```
design_offset(Δp) = tol · tanh( B_seg · Δp / tol )
```

- 在窗口之内，它**就是**线性的设计斜率；
- 在极端音区平滑收敛到 `target ± tol`，从而让整个数据集严格落在容差里；
- 它始终是**音高的单调函数**，因此模型仍然学得会，不会退化成随机。

`δ` 是整个数据集**共用的一个数**，用来把全库的时长加权响度精确对准目标。
`--tol 0` 关闭该窗口，完整保留段间音高动态，代价是会有部分片段超出容差。

### 方法本身的边界

容差窗在物理上装不下很大的段间音高关系：`±2 LU` 的空间对应的却是
`1.5 个八度 × 6 dB/oct ≈ ±5 LU`，两者直接矛盾。必然要牺牲一边，
本工具的做法是把这个取舍**明确摆出来、可测量**，而不是悄悄替你选一个。

## 用法

### 一、体检（不写任何音频）

```bash
python -m loudness_process audit path/to/dataset
```

在 `dataset/_loudness_audit/` 下生成 `audit_report.md` 与 `audit_files.csv`。
这一步回答的是"这份数据到底要不要动、哪几条有问题"。

### 二、处理（输出数据集）

```bash
python -m loudness_process process path/to/dataset path/to/output \
    --copy-sidecar --jobs 10
```

输出会镜像输入目录结构（`--keep-tree` 默认开启），可以直接替换原目录。
`--copy-sidecar` 会把标注文件（默认 `*.csv`，可用 `--sidecar-glob` 指定）一起复制过去。

嵌套目录会自动识别，也可以手动指定：

```bash
python -m loudness_process process in out --glob "**/wavs/*.wav"
```

一个文件就是一个来源（整段素材，不切片）：

```bash
python -m loudness_process process in out --preset stems --glob "*.wav"
```

### 三、验收（前后指标对照）

```bash
python -m loudness_process verify path/to/dataset path/to/output
```

### 四、听感对比

```bash
python -m loudness_process ab path/to/dataset path/to/output --n 10
```

自动挑出偏离设计音高线最远的若干片段，输出三个已统一电平的文件：
`AB_before.wav`、`AB_after.wav`，以及 `AB_interleaved.wav`
（奇数段 = 处理前、偶数段 = 处理后，同一句话连续听两遍）。

## 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `--target` | `-24.0` | 目标响度，LKFS（`-24` 对应 ATSC A/85；要 EBU R128 就用 `-23`） |
| `--tol` | `2.0` | 容差窗 ±LU，同时是设计曲线的饱和点（`0` = 关闭） |
| `--tp-max` | `-2.0` | 真峰值上限，dBTP |
| `--b-tilt-oct` | `6.0` | 段内设计斜率，dB/oct |
| `--b-seg-oct` | 同上 | 段间设计斜率，dB/oct |
| `--lam` | `0.6` | 部分校正系数（`1.0` = 把每个来源完全拉到目标） |
| `--dc-scope` | `pitch` | `pitch` = 电平跟随设计曲线；`constant` = 所有片段同一电平 |
| `--level-scope` | `corpus` | `corpus` = 整集对齐；`none` = 只做形状、不动电平 |
| `--no-limiter` | 关 | 关闭真峰值限幅 |
| `--lookahead`、`--release` | `0.012`、`0.200` | 限幅器时间常数，秒 |
| `--preset` | `auto` | `sliced`（片段共享文件名前缀）/ `stems`（一文件一来源）/ `auto` |
| `--glob` | 由 preset 决定 | 音频匹配模式，含 `**` 时递归 |
| `--keep-tree` | `1` | 保持输入目录结构 |
| `--copy-sidecar`、`--sidecar-glob` | 关 / `*.csv` | 复制标注文件到输出 |
| `--jobs` | `10` | 并行进程数 |
| `--limit` | `0` | 只处理前 N 个（调试用） |

### 怎么定参数

- **`--target`** —— 跟语料库其余部分保持一致，混训时才不会产生电平位移。
- **`--b-tilt-oct`** —— `+6` 是安全值。调低会发平，调高会夸张。
- **`--lam`** —— `0.6` 保留各来源自身的特征；`0.8` 更彻底。
- **`--tol`** —— 有交付容差就照着填；`0` 表示宁可保留完整的段间动态而接受散布。

## 输出

```
<out>/
  ...音频，目录结构与文件名同输入...
  _report.csv            逐片段：lufs_before, want, lufs_after, tp_after, ok,
                         gain_db, slope_seg_oct, source_slope_oct, note
  _groups.csv            逐来源：斜率 进 / 出
  _report.md             人读的汇总
  audit_report.md        （run / audit）处理前的状态
  audit_files_before.csv
  AB_*.wav               （ab）听感对比
```

其中 **`want`** 列是每条片段"按设计音高线应当具有的电平"。
如果你的声学模型接受显式的能量/动态通道，把这一列喂给它，
就能在不脱离响度规格的前提下把可控的动态找回来。

## 体检报告怎么看

四个数最关键：

| 指标 | 好 | 坏 | 含义 |
|---|---|---|---|
| **段内斜率**（中位 / sd） | 中位 ≈ +6，sd ≤ 1.5 | sd > 3 | 单次渲染能呈现的动态形状；sd 大说明各片段互相矛盾 |
| **段间斜率**（按来源） | 接近目标，sd ≤ 2 | 范围 −5 … +17 dB/oct | 音高升八度时响度涨多少；负值是限制器的指纹 |
| **段间残差** | < 1.0 dB | > 2 dB | 音高解释不掉的电平散布 —— **这才是"忽大忽小"的量** |
| **落进 ±tol 的比例** | 100 % | < 90 % | 是否满足交付规格 |

报告还会列出偏离设计音高线最远的片段。偏差大于 4 dB 通常意味着取错了 take、
切片切错，或原采集增益不一致，值得人工回看。

## 度量口径

- **积分响度**：ITU-R BS.1770 —— K 加权（系数按实际采样率重算）、400 ms 块 / 75 % 重叠、
  −70 LKFS 绝对门限、−10 LU 相对门限。与 `ffmpeg` 的 `ebur128` 对拍误差 **≤ 0.05 LU**。
- BS.1770-3 与 -4 的积分响度**完全一致**，区别只在真峰值的细节。
- **一律按单声道分析。** 把 dual-mono 当立体声求和会比按单声道高 **3.01 LU**，
  这是让语料库不一致最常见的一个坑。
- **真峰值**：4× 过采样峰值检测。
- **短片段**：掐掉首尾各 10 % 会让积分值漂移约 0.12 LU（中位）/ 0.29 LU（p90），
  所以对几秒钟的片段，比 ±0.5 LU 更紧的容差没有实际意义。

## 已知限制

1. **容差窗会压缩段间音高动态。** `±2 LU` 装不下 `1.5 个八度 × 6 dB/oct`。
   想完整保留就设 `--tol 0`，接受相应的散布。
2. **已经被限制器压死的素材救不回来。** 工具能重建"音高→响度"的宏观关系，
   但源素材里已经被削掉的动态无法恢复。这类数据在体检里表现为段内斜率 sd 很大、
   段间斜率接近 0 甚至为负。
3. **斜率按来源估计，不逐片段。** 5–15 s 的片段音高跨度太小，
   单独拟合的散布可达 7 dB/oct。需要把同一来源的片段池化后再算——
   用共享文件名前缀（`--preset sliced`）就是为此。
4. **`--dc-scope pitch` 需要可用的音高。** 纯气声或完全无浊音的片段会回退到数据集参考音高。
